# Markdown 원고 작성과 제출

신규 콘텐츠의 기본 제출 방식은 로컬 Codex CLI에서 Markdown과 이미지를 작성하고 별도 브랜치의 Draft PR로 제출하는 것입니다. 별도 유료 OpenAI API 호출은 사용하지 않습니다.

## 먼저 알아둘 운영 상태

현재 GitHub Actions 게시 및 `PAGES_ACTIONS_ENABLED=true`가 활성화되어 있습니다. PR 검증은 배포하지 않으며 사람이 main에 병합하면 실제 자동 배포됩니다. `draft: true`는 HTML·목록·사이트맵에서 제외됩니다. 자세한 검증·게시 동작은 [게시 운영](publishing.md)을 따릅니다.

## 파일 형식

`content/articles/<slug>.md`에 UTF-8 파일을 추가합니다. 아래 예제와 [검증용 초안](../content/articles/boxing-first-class.md)은 기존 형식 확인용으로, `draft: true`와 기존 이미지 참조를 보존합니다. 정기 콘텐츠 제출 시에는 신규 `<slug>`에 맞춰 원고·canonical·신규 이미지 경로를 작성하고 `draft: false`로 제출합니다.

```markdown
---
title: "복싱 첫 수업 준비 안내"
description: "처음 복싱을 시작하는 분을 위한 수업 준비 안내."
slug: "boxing-first-class"
published: "2026-10-10"
updated: "2026-10-10"
keywords: ["초보 복싱", "복싱 입문"]
canonical: "https://redboxing-gym.github.io/articles/boxing-first-class.html"
kicker: "BEGINNER BOXING"
lead: "첫 수업을 준비할 때 확인할 사항입니다."
hero_image: "/assets/img/freetime.webp"
hero_alt: "레드복싱 운동 공간"
tags: ["beginner", "boxing"]
related: ["/articles/boxing-diet-beginner.html"]
draft: true
---

## 첫 수업 준비

본문을 작성합니다.
```

## 메타데이터 규칙

| 필드 | 규칙 |
| --- | --- |
| title / description | 비어 있지 않은 문자열. 검색 결과에 적합한 자연스러운 한국어 |
| slug | 영문 소문자·숫자·단어 사이 하이픈. 파일명과 일치 |
| published / updated | 따옴표로 감싼 YYYY-MM-DD. 수정일은 작성일 이후 또는 같은 날 |
| keywords | 한 개 이상 문자열 목록 |
| canonical | `https://redboxing-gym.github.io/articles/<slug>.html`과 정확히 일치 |
| kicker / lead | 카드·대표 영역 문구 |
| hero_image / hero_alt | 실제 존재하는 `/assets/img/` 파일의 경로와 대체 텍스트 |
| tags | 선택 문자열 목록. 관련 글 우선순위에 사용 |
| related | 선택 문자열 목록. 공개된 기존·신규 글의 `/articles/...html` 경로 |
| draft | 따옴표 없는 `true` 또는 `false`, 반드시 명시 |

제목은 템플릿이 H1으로 만듭니다. 본문은 `##`부터 사용합니다. 문단, 목록, 강조, 링크, 이미지, 표, 코드 블록을 지원합니다. 원시 HTML·스크립트·iframe·HTML 자동 링크는 지원하지 않습니다. 링크는 `[문구](URL)`로 작성합니다. 문의 CTA·지점 전화·카카오톡은 템플릿에서 제공합니다.

파일의 공개 URL은 slug로 결정되며 기존 HTML URL과 충돌하면 실패합니다. `draft: false`가 main 이력에 반영되면 배포가 아직 비활성 상태여도 공개 URL을 예약·보호합니다. 이후 slug·canonical·작성일을 바꾸거나 원고를 삭제하거나 초안으로 되돌릴 수 없습니다. 제목·설명·본문·키워드·이미지·관련 글 등의 수정은 허용합니다. `updated`는 해당 글의 main 이력에 기록된 가장 최근 수정일보다 앞설 수 없습니다. 같은 날 여러 번 수정하는 것은 허용합니다.

기존 HTML 아티클 5개는 별도 정책으로 파일 전체를 보존합니다. 신규 Markdown 글의 본문 수정 허용과 충돌하지 않습니다. PR 작업 브랜치에서만 잠시 `draft: false`였다가 최종 원고를 초안으로 되돌린 상태는 main에 공개 상태가 반영되지 않았다면 URL을 잠그지 않습니다. 빌드 검토용 임시 공개 상태를 main에 커밋하지 마세요.

공개 글의 내용을 복구할 때도 URL과 작성일을 유지하고 수정일이 뒤로 돌아가지 않도록 합니다. 예전 커밋을 그대로 revert하여 수정일을 과거로 되돌리지 말고, 복구할 본문과 현재 정책에 맞는 `updated`를 담은 PR을 제출하세요.

`draft: true`도 메타데이터·본문 형식·본문 내부 링크를 검사하지만 HTML 파일을 만들지 않습니다. 공개 목록·관련 글·사이트맵에도 포함되지 않습니다. 초안 URL로 링크하면 검증이 실패합니다. 전체 생성 페이지의 SEO 검사는 공개 원고에 적용됩니다.

## Codex로 신규 원고와 이미지 작성

1. [AGENTS.md](../AGENTS.md), [주제 대장](../ARTICLE_IDEAS.md), [키워드](../SEO_KEYWORDS.md), 실제 `articles/` HTML과 `content/articles/`의 공개·초안 원고를 확인합니다. 제목뿐 아니라 검색 의도와 본문 범위도 비교하고 겹치면 새 관점을 정하거나 보고합니다.
2. 누구나 즐기는 생활체육 복싱을 친근하고 정확하게 설명합니다. 장비 구매 부담·체력 부족·진입 난이도를 불필요하게 강조하지 않습니다. 시설·가격·운영시간·건강 효과는 확인된 근거만 사용합니다. 기존 원고도 최신 사실의 보증으로 보지 않습니다. 무료체험은 운영하지 않으므로 무료체험 홍보 표현을 쓰지 않습니다.
3. 기획 단계에서 본문 구조와 대표 이미지·4컷 요약 만화·필요한 설명 이미지를 함께 설계합니다. 정기 콘텐츠 PR은 신규 `content/articles/<slug>.md` 1개와 해당 글에 실제 사용되는 신규 WebP 이미지들로 구성하며 파일 개수에 고정 제한을 두지 않습니다. `ARTICLE_IDEAS.md` 등 기획 문서는 참고만 하고 기존 사이트 코드·아티클·이미지·스크립트·워크플로도 변경하지 않습니다.
4. 위 계약으로 UTF-8 원고를 완성하고 `draft: false`로 제출합니다. GitHub Draft PR 상태와 Markdown `draft` 값은 별개입니다. PR 병합 전에는 실제 게시되지 않으며 사람의 PR 병합 승인이 게시 승인입니다. 병합 후 GitHub Actions가 검증·자동 배포합니다. 기존 `draft: true` 검증용 초안은 유지합니다. 사용한 출처와 확인일을 PR 설명에 기록하고 근거가 필요한 본문 주장에는 출처 링크를 제공합니다.
5. 아래 이미지 정책에 따라 완성 본문을 기준으로 이미지를 제작·배치하고 실제 디코딩·표시 검증을 수행합니다. [게시 운영](publishing.md)의 검증도 모두 실행한 뒤 [Draft PR 절차](external-pr-integration.md)로 제출합니다.

## 이미지 제작과 검증

- 신규 이미지는 Codex 내장 `image_gen`으로 독창적인 래스터 이미지를 생성합니다. 모든 최종 이미지는 WebP로 저장합니다. 기존 이미지를 신규 생성 이미지로 취급하지 않으며 SVG·HTML·CSS 그림으로 대체하지 않습니다. 생성 도구를 사용할 수 없거나 추가 과금이 필요하면 유료 서비스로 전환하지 않고 보고합니다.
- 대표 이미지: 실제 사이트 표시 영역과 반응형 레이아웃에 적합한 해상도·비율을 선택합니다. `hero_image`로 지정하고 중요한 피사체를 중앙에 배치해 히어로와 카드의 잘림을 고려합니다. 픽셀 크기·비율의 고정 필수값은 없습니다.
- 4컷 요약 만화: 완성된 본문을 바탕으로 제작해 신규 아티클 초반(짧은 도입 뒤, 상세 설명 전)에 Markdown 이미지로 삽입합니다. 만화만 보아도 핵심 메시지를 이해할 수 있어야 합니다. 주제별 연출은 자유롭게 하되 모바일에서 확대 없이 읽기 쉬운 세로형 단일 이미지를 기본으로 합니다. 짧은 문장·큰 글자·분명한 읽기 순서를 사용하며 본문의 사실·조건을 왜곡하지 않습니다.
- 본문 설명 이미지: 이해에 도움이 되는 도해·동작 설명 등 필요한 만큼 생성합니다. 개수·비율에 고정 제한을 두지 않으며 이미지 수를 늘리기 위한 장식성 이미지는 만들지 않습니다.
- 경로: `assets/img/<slug>-hero.webp`, `assets/img/<slug>-comic.webp`, `assets/img/<slug>-<설명>.webp` 등 충돌 없는 신규 경로를 사용합니다. 대표·설명 이미지 이름은 예시입니다. 4컷 요약 만화는 `<slug>-comic.webp`처럼 `-comic.webp` 접미사를 사용합니다. 이 접미사는 CSS의 만화 전용 최대 표시 너비를 적용하기 위한 규칙입니다. `hero_image`와 본문 `![대체 텍스트](/assets/img/파일명.webp)` 참조를 실제 파일에 맞춥니다. 모든 제출 이미지는 해당 글의 대표 또는 본문에서 실제로 사용되어야 합니다.
- 디코딩: 모든 최종 파일을 실제 이미지 디코더로 열어 픽셀 데이터를 끝까지 읽고 WebP 형식·실제 너비와 높이를 확인합니다. 확장자·파일명·헤더만 확인하는 것으로 대신하지 않습니다. 디코딩 실패나 선택한 제작 규격과의 불일치가 있으면 제출하지 않습니다. 크기는 기록·품질 확인 대상이며 고정 상한·하한이 아닙니다. 기존 빌드 검사는 이 검증을 대신하지 않습니다.
- 내용·표시 검토: 파일 존재, 경로, 의미 있는 대체 텍스트와 본문 내용의 일치를 확인합니다. 데스크톱·모바일에서 대표/카드의 잘림, 본문 이미지의 가로 넘침, 만화의 글자·읽기 순서를 확인합니다. PR 설명에 이미지별 역할·경로·생성 방식·디코딩 도구·형식·픽셀 크기·표시 검토 결과를 기록합니다.

## 실제 표시 영역과 권장 규격

다음은 `templates/article.html`, `templates/article-card.html`, `css/article.css`, `css/styles.css`, 템플릿이 불러오는 Bootstrap 5.2.3 및 Markdown 렌더링 코드의 분석 결과입니다. 권장 예시는 필수 규격이나 기존 시스템의 크기 제한이 아닙니다.

| 용도 | 현재 표시 동작 | 제작 권장 예시 |
| --- | --- | --- |
| 대표 이미지 | `width: 100%`, `max-height: 32rem`, `object-fit: cover`. 고정 `aspect-ratio`가 없고 원본 비율·표시 너비에 따라 높이가 정해지며 최대 높이에 걸리면 잘림 | 가로형 16:9, 1600×900 또는 1920×1080을 출발점으로 삼되 피사체·표시 품질에 맞춰 조정. 가장자리의 핵심 문구는 피함 |
| 카드의 대표 이미지 | 데스크톱 카드 내부 열 비율 0.9:1.1 중 이미지가 앞 열을 사용. 이미지 `width/height: 100%`, `min-height: 18rem`, `object-fit: cover`; 카드 높이는 본문에 따라서도 달라짐. 991.98px 이하에서 세로 배치 | 히어로와 다른 비율로 잘릴 수 있으므로 중앙 피사체 중심으로 구성. 카드에 반드시 읽어야 하는 글자를 넣지 않음 |
| 4컷 요약 만화 | 일반 Markdown 이미지에 `.article-body img[src$="-comic.webp"]` 적용. 컨테이너 너비 이내, 최대 30rem이며 원본 비율 유지·작은 원본 강제 확대 없음 | 위아래로 읽는 1:3~1:4 정도의 세로형을 출발점으로 선택. CSS로 표시 너비가 줄어들어도 모바일에서 확대 없이 글자를 읽을 수 있는지는 별도 검토 |
| 본문 설명 이미지 | `.article-body img` 적용. 컨테이너 너비 이내, 최대 40rem이며 원본 비율 유지·작은 원본 강제 확대 없음 | 설명에 맞춰 가로·세로·정사각형을 자유롭게 선택. 실제 표시 크기와 설명의 가독성을 확인 |

기본 루트 글자 크기 16px 및 Bootstrap 기본 컨테이너 기준으로, 히어로의 최대 콘텐츠 너비는 1224 CSS px(1320px 컨테이너에서 좌우 48px 패딩 제외), 최대 높이는 512 CSS px입니다. 360px 화면에서는 너비 약 312px, 390px에서는 약 342px입니다. 예를 들어 16:9 원본은 1224px 너비에서 자연 높이가 688.5px이므로 최대 높이에 걸려 위아래가 잘릴 수 있습니다. 모바일에서는 최대 높이에 걸리지 않으면 원본 비율을 따릅니다. 이 CSS 표시 치수는 원본 파일의 허용 픽셀 크기 제한이 아닙니다.

**현재 본문 이미지의 반응형 표시:** `scripts/build.py`가 생성하는 일반 Markdown `<img>`에 `css/article.css`의 `.article-body img`가 적용됩니다. 본문 grid 자식의 `min-width: 0`과 이미지의 `max-width: min(100%, 40rem)`으로 컨테이너 너비를 넘지 않도록 축소합니다. `-comic.webp`로 끝나는 이미지 경로에는 `max-width: min(100%, 30rem)`을 적용합니다. `width: auto`, `height: auto`로 원본 가로세로 비율을 유지하고 작은 원본 이미지는 강제 확대하지 않습니다. `display: block`, `margin-inline: auto`로 가운데 정렬합니다. 기본 루트 글자 크기 16px에서 40rem은 640 CSS px, 30rem은 480 CSS px이며 이는 표시 상한으로, 원본 파일의 해상도 제한이 아닙니다. 대표 이미지와 카드 이미지의 기존 표시 규칙은 유지됩니다.

CSS가 이미지의 가로 넘침을 방지하더라도 4컷 만화의 글자가 모바일에서 확대 없이 읽기 쉬운지는 별도로 검토합니다. 예를 들어 360px·390px 화면에서 실제 표시 크기로 글자 크기·읽기 순서·핵심 메시지 전달을 확인합니다. 해상도를 높이는 것만으로 축소 후 가독성을 보장할 수 없으므로 필요하면 짧은 문장과 큰 글자로 연출을 조정합니다. 실제 이미지 디코딩·대체 텍스트·본문 참조 확인도 유지하며, 기존 빌드 검사 통과만으로 디코딩이나 모바일 가독성 검토를 대신하지 않습니다.

## 검토와 게시

1. PR의 `content-check` 성공 여부와 원고를 확인합니다.
2. Actions 실행에서 `site-review-<run_id>`를 다운로드합니다.
3. 압축을 풀어 `python -m http.server 8000`으로 실행하고 `http://localhost:8000/`를 확인합니다. 루트 상대 경로 때문에 파일을 직접 더블클릭하는 방식은 권장하지 않습니다.
4. 정기 콘텐츠 원고는 `draft: false`이므로 검토 아티팩트에서 완성 페이지를 확인합니다. 기존 검증용 초안은 계속 `draft: true`로 유지하고 해당 초안 HTML이 없는지 확인합니다. 검토 아티팩트 생성은 실제 Pages 게시가 아닙니다.
5. 사람은 원고·실제 디코딩한 이미지·검증 결과를 확인하고 게시를 승인할 때 GitHub Draft PR을 검토 가능한 상태로 전환해 병합합니다. Markdown `draft` 값을 나중에 바꾸는 별도 PR은 필요하지 않습니다. 병합 후 GitHub Actions가 검증에 성공하면 자동 배포합니다.

PR 검사 성공만으로 승인이나 병합이 이루어지지 않습니다.
