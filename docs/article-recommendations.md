# 빌드 시 관련 글 자동 추천

`scripts/recommendations.py`의 순수 함수 `recommend_related(article, catalog)`가 공개 글 최대 3개를 반환합니다. `scripts/build.py`는 모든 공개 Markdown 페이지를 만들 때 이를 호출합니다. 새 글이 추가되면 기존 Markdown 페이지의 추천도 같은 빌드에서 다시 계산됩니다. 템플릿·디자인은 변경하지 않으며 본문이나 원고 파일을 수정하지 않습니다.

## 공개 후보와 하위 호환

- 후보는 전체 공개 Markdown과 레거시 HTML 5개입니다. `draft: true`, 자기 URL, 중복 URL을 제외합니다. 다른 공개 URL이 3개 이상이면 정확히 3개, 아니면 가능한 개수만 반환합니다. 초안 페이지는 생성하지 않습니다.
- 레거시는 기존 `content/legacy-articles.json`의 태그·제목·설명·카테고리와 보호 HTML에서 읽은 게시일을 사용합니다. 없는 키워드·lead·kicker·태그는 빈 값으로 처리합니다. `draft`가 없는 레거시는 공개로 취급합니다. 레거시 HTML 원본·출력·기존 추천 영역은 그대로 보존합니다.
- `related` 필드는 더 이상 사용하지 않습니다. 새 원고에서는 생략합니다. 기존 값은 파싱 후 버리며 타입·URL 검사나 추천에 사용하지 않습니다. 오래된 URL·초안 URL·자기 URL이 남아 있어도 빌드에 영향을 주지 않습니다. 본문 링크·앵커·이미지의 기존 검사는 계속 적용합니다.
- URL·canonical·작성일·수정일 보호, 메인·목록·필터·사이트맵·SEO·이미지·배포 계약은 변경하지 않습니다. 추천만 바뀐 출력은 원고 `updated`를 자동으로 변경하지 않습니다.

## 텍스트 정규화

태그·키워드·제목·description·lead·kicker만 사용합니다. 본문, slug, URL, 출처 링크, 작성·수정일은 주제 점수에 사용하지 않습니다. 본문 전체의 공통 CTA나 참고 자료가 추천 근거로 섞이는 것을 피합니다.

Python 표준 라이브러리로 NFKC 정규화·casefold 후 유니코드 단어를 추출합니다. 코드의 `KOREAN_SUFFIXES`에 있는 흔한 조사를 순서대로 최대 한 번 제거하되, 남는 말이 두 글자 이상이거나 명시적 한 글자 주제 예외일 때만 적용합니다. 단독 숫자, 일반 단어, 예외를 제외한 한 글자 토큰은 버립니다. 한 글자 예외는 `잽`, `훅`, `땀`입니다. `잽을`과 `잽`은 연결되지만 `잽싸게`의 부분 문자열은 일치하지 않습니다.

`GENERAL_WORDS`에는 복싱·운동·초보자·기초·경기·분석·훈련·가이드·연습·레드복싱·지점명 등 사이트·독자·글 형식을 나타내는 일반 단어를 둡니다. 일반 단어만 남은 태그·키워드는 근거가 되지 않습니다. 예를 들어 `초보 복싱`은 점수가 없고, `복싱 잽`과 `잽`은 같은 주제 구문으로 비교합니다. 이 목록은 원고의 허용 태그 사전이 아니며 새 단어를 제한하지 않습니다.

태그·키워드의 남은 토큰열을 구문으로 사용합니다. 구문 교차 일치는 **일반 단어 제거 후 연속된 토큰열**끼리 비교하며, 단어 내부 부분 문자열이나 문장 필드 경계를 넘는 구문은 비교하지 않습니다. 중복 태그·키워드·단어를 여러 번 써도 같은 근거의 점수는 늘어나지 않습니다.

## 관련성 점수

`relevance_score(left, right)`는 다음 점수의 합입니다. 모든 비교는 정규화 후 이루어집니다. 각 행은 서로 다른 일치를 최대 3개까지만 계산하고, 양방향 교차 일치는 합집합으로 중복 제거합니다. 여러 종류의 근거가 같은 주제를 확인하면 행별 점수를 합산합니다.

| 근거 | 일치당 점수 | 행별 최대 |
| --- | ---: | ---: |
| 태그 ↔ 태그 구문 동일 | 24 | 72 |
| 키워드 ↔ 키워드 구문 동일 | 20 | 60 |
| 태그 ↔ 키워드 구문 동일 | 16 | 48 |
| 태그·키워드 구문 ↔ 상대 제목 | 8 | 24 |
| 태그·키워드 구문 ↔ 상대 description·lead·kicker | 4 | 12 |
| 제목 ↔ 제목의 단어 동일 | 2 | 6 |
| 제목 단어 ↔ 상대 description·lead·kicker 단어 | 1 | 3 |

태그·키워드의 구체적인 일치가 단순 제목 단어보다 높은 점수를 갖습니다. 설명끼리의 단어 중복만으로는 점수를 주지 않습니다. 카테고리·최신성·수동 `related`는 주제 점수를 올리지 않습니다. 점수는 대칭이며 기본 입력을 변경하지 않습니다.

## 네 단계 선정과 정렬

후보마다 처음 해당하는 단계 하나를 부여합니다. 앞 단계에서 이미 선택한 글은 뒤 단계에 중복되지 않습니다.

1. **직접 연관:** 관련성 점수 4점 이상. 구체 구문이 상대 설명에 한 번 나타나거나, 제목의 의미 있는 단어 두 개가 겹치는 정도부터 해당합니다. 다른 카테고리여도 우선합니다.
2. **동일 카테고리:** 1차가 아닌 글 중 같은 대표 카테고리.
3. **연관 카테고리:** 1·2차가 아닌 글 중 아래 두 카테고리에 속한 글.
4. **최종 보충:** 그 외 나머지 공개 글.

| 현재 카테고리 | 3차 후보 카테고리 |
| --- | --- |
| boxing-technique | boxing-beginners, workout-programs |
| boxing-beginners | boxing-technique, workout-programs |
| exercise-science | workout-programs, boxing-technique |
| workout-programs | exercise-science, boxing-beginners |
| match-analysis | boxing-technique, combat-history |
| combat-culture | combat-history, match-analysis |
| combat-history | match-analysis, combat-culture |

전체 정렬 키는 **단계 오름차순 → 점수 내림차순 → 게시일 최신순 → URL 오름차순**입니다. 3차의 두 카테고리는 한 후보 풀로 비교하며 표의 기재 순서로 점수·게시일·URL 우선순위를 덮어쓰지 않습니다. 수정일은 정렬에 사용하지 않습니다. 무작위·현재 시각·파일 열거 순서를 사용하지 않습니다. 방어적으로 같은 URL이 여러 번 들어오면 한 번만 선정하고, 동일 정렬 키의 중복 레코드는 관련 메타데이터의 고정 JSON 서명으로 결정합니다. 실제 빌더는 중복 공개 URL을 기존 정책대로 거부합니다.

## 한계와 검수

형태소 분석·동의어 사전·외부 API·LLM·서비스·런타임 JavaScript·새 의존성은 사용하지 않습니다. 조사는 제한적으로만 처리하므로 활용형·복합명사·동의어를 모두 이해하지 못합니다. 정확한 태그·키워드와 제목·설명이 중요합니다. 일반 단어 목록·배점은 설명 가능한 초기 규칙이며 의미상의 최적 추천을 보장하지 않습니다. 후보가 충분할 때 3개를 채우므로 마지막 보충은 주제 연관성이 낮을 수 있습니다.

`tests/test_recommendations.py`는 점수·일반 단어 억제·교차 일치·7개 연관 카테고리·각 보충 단계·날짜/URL 동점·중복/초안/자기 제외·수동 필드 무효·레거시 결측 메타데이터를 검사합니다. 실제 빌드 테스트는 새 글 공개·초안 전환에 따른 기존 페이지 재계산, `related` 생략/무효 값 허용, 반복 빌드의 전체 파일 해시, 모든 공개 추천 패널과 보호 원본 바이트를 검증합니다. 기존 카테고리·태그·콘텐츠 회귀 테스트의 수동 추천 기대값만 새 계약으로 갱신합니다.

필수 검증은 [게시 운영](publishing.md)을 따릅니다. `python -m unittest discover -s tests -p test_recommendations.py -v`로 추천 전용 검사를 실행할 수도 있습니다. 정기 콘텐츠 생성 러너와 외부 프리뷰 저장소의 변경은 이 구현 범위에 포함되지 않습니다.
